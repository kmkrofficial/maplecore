# MAPLE — Data

Nothing under `data/`, `models/`, `.cache/` or `benchmarks/results/` is
committed. Everything is regenerated by the scripts below.

## 1. Download

```bash
# Recommended: keep the multi-GB caches off C:
export HF_HUB_CACHE="$PWD/.cache/huggingface/hub"
export HF_DATASETS_CACHE="$PWD/.cache/huggingface/datasets"

python scripts/download_data.py              # all public data
hf auth login                                # once; needs accepted Llama-3 licence
python scripts/download_data.py --only teacher
```

| Item | Source | Size / rows | Used by |
|---|---|---|---|
| NarrativeQA | `deepmind/narrativeqa` | train 32,747 · val 3,461 · test 10,557 questions (full stories, ~10 GB) | oracle, 07 |
| HotpotQA distractor | `hotpotqa/hotpot_qa` | train 90,447 · val 7,405 | oracle, 05, 06, 07 |
| SQuAD v1.1 | `rajpurkar/squad` | val 10,570 | 06 |
| Gutenberg | #1661 Sherlock, #1342 P&P, #84 Frankenstein, #11 Alice | 4 books → `data/gutenberg/` | 02, 03, 04, needle training |
| Encoders | `BAAI/bge-small-en-v1.5` (384-d, default), `all-MiniLM-L6-v2` (384-d), `nomic-embed-text-v1.5` (768-d) | — | everything |
| Teacher | `meta-llama/Meta-Llama-3-8B-Instruct` (gated) | ~16 GB, run in 4-bit NF4 | oracle generation |

`data/MANIFEST.json` records row counts, dataset fingerprints and model paths
for every download.

## 2. Oracle labels

```bash
python scripts/generate_oracle.py        --split train      --max-samples 2000
python scripts/generate_oracle.py        --split test       --max-samples 500
python scripts/generate_oracle_hotpot.py --split train      --max-samples 2000
python scripts/generate_oracle_hotpot.py --split validation --max-samples 500
```

Outputs `data/oracle/{narrativeqa,hotpotqa}_{split}.json`. Train files feed
`scripts/train_generalist.py`; held-out files feed benchmark 01.
NarrativeQA train/test are different stories; HotpotQA train/validation are
different questions.

Options: `--max-tokens` (teacher context budget, default 1,536 = v0.2.0),
`--max-per-doc` (NarrativeQA questions per story, default 5),
`--teacher` (any HF causal LM with eager attention), `--resume`.

### Label definition

The teacher reads `[instruction][block_0]\n[block_1]\n…\n\nQuestion: q\nAnswer:`.
For the final token, the attention row of every layer is recorded. Per block:

* `attention_scores` — last layer, mean over heads, summed over the block's tokens
* `attention_scores_all_layers` — same, averaged over all layers

`top_5_block_ids` = the 5 highest `attention_scores` → positive training labels.

### How the attention row is computed (`--attn-impl`)

| | `fast` (default) | `eager` (reference) |
|---|---|---|
| Teacher attention kernel | PyTorch SDPA | eager (full `heads × L × L` matrix per layer) |
| Last-token row | recomputed from the post-RoPE q/k that SDPA receives: `softmax(q_last·Kᵀ·scale + mask)` | read from the eager weight matrix by a forward hook |
| Batching | left-padded batches (`--batch-size`), padded keys masked, LM head skipped | one prompt at a time |
| Throughput, Llama-3-8B 4-bit, RTX 4090 Laptop | 2.3 samples/s @ 1,536 tok · 0.77 @ 4,096 | ≈ 0.9 @ 1,536 |

Agreement on 200 HotpotQA validation samples (`scripts/compare_oracles.py`,
fast vs eager): **top-5 identical for 200/200**, max per-block score difference
1.1e-4 (fp16 vs fp32 rounding), mean Spearman 0.9995. `tests/test_oracle_fast.py`
checks the same on a random tiny Llama, including padded batches.

Each sample records `attn_impl`. In `data/oracle/` (1,536 budget),
`hotpotqa_validation.json` and the first 475 samples of `narrativeqa_test.json`
were generated with `eager`; everything else with `fast`.

The fast path is compute-bound (~3k tokens/s); larger batches do not help
beyond 2–4. One pitfall, handled in `score_batch`: an unpadded batch lets HF
drop the attention mask, and SDPA's `is_causal` path ran ~25× slower on
Windows at 4k tokens, so every batch keeps one masked pad column.

### Schema (v2)

```jsonc
{
  "metadata": {"schema_version": 2, "dataset": "...", "split": "...", "teacher_model": "...",
               "max_context_tokens": 1536, "chunk_size": 500, "top_k": 5, "num_samples": 0,
               "complete": true, "skipped": {...}},
  "samples": [{
    "id": "...", "domain": "narrative_qa | hotpot_qa", "question": "...", "answers": ["..."],
    "blocks": [{"id": 0, "text": "..."}],           // blocks that fit in the teacher context
    "top_5_block_ids": [3, 0, 7, 1, 4],             // oracle positives
    "attention_scores": {"3": 0.041, ...},
    "attention_scores_all_layers": {"3": 0.012, ...},
    "gold_block_ids": [3],                           // dataset evidence (may be empty)
    "num_blocks_in_context": 12, "num_blocks_total": 410, "seq_len": 1520
    // NarrativeQA: "document_id"; HotpotQA: "type", "level", "gold_paragraph_block_ids"
  }]
}
```

`scripts.oracle_common.load_oracle_samples()` also reads the v0.2.0 (v1)
formats (`all_block_texts` / `labels`).

## 3. Trained models

```bash
python scripts/train_generalist.py --seed 42   # -> models/maple_generalist.pth
```

Writes the checkpoint plus `*.train.json` (data counts, history, seed) and
`*.hardware.json`. Benchmarks default to `models/maple_generalist.pth`.

## 4. Benchmark outputs

All benchmarks write JSON (and PNG plots) to `benchmarks/results/`. See
[METRICS.md](METRICS.md) for what each number means.

## 5. Run registry (`runs/`)

Every oracle, training, benchmark, aggregation and download run goes through
`scripts/runlog.py`. Nothing lives only in a terminal. `runs/` is gitignored and
never pruned.

```
runs/index.jsonl                      one line per finished run (append-only)
runs/<YYYYMMDD-HHMMSS>_<kind>_<tag>/
    config.json      arguments, argv, git commit/branch/dirty/diff hash,
                     environment (platform, python, torch, CUDA, GPU, packages), data manifest
    run.log          everything logged or printed during the run
    metrics.jsonl    per-epoch / summary metrics (step, time, ...)
    items/*.jsonl    per-question outputs (rankings, scores, predictions)
    artifacts.json   path, role, bytes, sha256 of every recorded output
    artifacts/       copies of small (< 50 MB) outputs
    hardware.json    CPU / RAM / VRAM usage
    summary.json     status (completed | failed), traceback, duration, final metrics
runs/legacy_v1/      v0.2.0-era logs, results and checksums, imported once
```

A trained checkpoint `models/x.pth` gets `models/x.pth.card.json`: run id, config,
encoder, seed, data files with checksums, validation metrics and git state.
A run that crashes or is interrupted is still recorded, with `status: "failed"`.

```bash
python scripts/runlog.py list [--kind bench]
python scripts/runlog.py show <run_id>
python scripts/runlog.py import-legacy
```
